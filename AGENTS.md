# Working on Galaxy Studio

Read `README.md`, `research/README.md`, `research/FINDINGS.md` and
`research/AI_HANDOFF.md` before drawing conclusions from older experiment reports.
The project is predominantly AI-developed/researched; retain that disclosure.

- Keep user-facing UI, documentation and new research notes in English.
- Use this checkout. Do not create worktrees unless the user requests one.
- Preserve unknown bytes, explicit ID namespaces, mode-specific preset tables,
  copy-on-write behavior, rollback and Undo/Redo. Do not replace them with guessed
  semantics or normalize imported files just because they look unusual.
- Distinguish static proof, controlled HP/aura/resident-data probes, natural gameplay,
  user reports and editor-only checks. Do not turn configured capacities into claims
  of playable campaigns or absolute limits.
- Match executable hashes before using recorded guest virtual addresses. Heap
  addresses and old process IDs are historical observations, never current pointers.
- Do not automatically run experimental EBOOT/save tools or old inverse journals.
  They are outside ordinary editor workflows and need a matching research task.
- Game fixtures stay private. Use environment variables described in DEVELOPMENT.md;
  never commit game archives, MMD/DAT files, executable binaries, saves or RAM dumps.
- Run checks appropriate to the change. Release verification requires complete
  source-bound reports, no skipped fixture-dependent cases in the release run, and
  testing the extracted portable package. Preserve previously distributed ZIPs.
- Resolve routine work autonomously within the user's scope. No extra approval or
  multi-agent delegation is required by this file.
